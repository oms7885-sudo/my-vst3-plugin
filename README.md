# Bass To MIDI (VST3)

오디오 인터페이스로 들어오는 베이스 소리를 실시간으로 MIDI 노트로 바꿔 주는 큐베이스용 VST3 플러그인입니다.

## 다운로드

1. 저장소 위쪽의 **Actions** 탭을 엽니다.
2. 가장 최근의 초록색 체크 표시가 있는 빌드를 누릅니다.
3. 아래쪽 **Artifacts**에서 `BassToMIDI-VST3-Windows`를 내려받습니다.
4. 압축을 풀면 나오는 `Bass To MIDI.vst3` 폴더를 `C:\Program Files\Common Files\VST3`에 복사합니다.

## 큐베이스 설정

1. **오디오 트랙**을 하나 만들고, 입력을 베이스가 꽂힌 오인페 입력으로 설정합니다. 모니터링을 켭니다.
2. **인스트루먼트 트랙**을 만들고 악기로 `Bass To MIDI`를 고릅니다.
3. 플러그인 창 위쪽의 **사이드체인 버튼**을 켭니다.
4. 1번 오디오 트랙의 **Sends** 또는 **출력 라우팅**에서 `Bass To MIDI - Side-Chain`으로 신호를 보냅니다.
   - 플러그인 화면에 `Input: OK`가 나오고, 줄을 치면 음 이름이 표시되면 연결된 것입니다.
5. 소리를 낼 악기(신스, 드럼 등)를 다른 **인스트루먼트 트랙**에 올립니다.
6. 그 트랙의 **MIDI 입력**을 `Bass To MIDI`로 바꾸고 녹음 대기(또는 모니터)를 켭니다.
   - 이제 베이스를 치면 그 악기가 따라서 연주하고, 녹음하면 MIDI로 기록됩니다.

> 연결이 제대로 됐는지 확인하려면 **Monitor tone**을 켜 보세요. 검출된 음이 간단한 소리로 들립니다.

## 노브 설명

| 노브 | 역할 | 팁 |
|---|---|---|
| Threshold | 이 음량보다 작으면 무음으로 처리 | 미터의 흰 선. 줄을 안 칠 때 잡음보다 약간 위로 |
| Tolerance | 음정 판정 기준 (낮을수록 엄격) | 엉뚱한 음이 나오면 낮추고, 놓치는 음이 많으면 올리기 |
| Stability | 같은 음정이 몇 번 연속 나와야 노트를 켤지 | 낮추면 반응이 빠르고, 높이면 오검출이 줄어듦 |
| Re-trigger | 피킹 순간의 어택(고음 성분, 음량 상승)이 이만큼 튀면 새로 친 것으로 처리 | 같은 음 반복이 안 잡히면 낮추기, 안 친 음이 생기면 올리기. Off 가능 |
| Velocity | 피킹 세기를 벨로시티에 반영하는 정도 | Fixed = 항상 100 |
| Lowest / Highest | 검출할 음역 | 4현은 E0(큐베이스 표기)부터 |
| Transpose | 출력 MIDI 음을 반음 단위로 이동 | +12 = 한 옥타브 위 |
| MIDI Ch | 출력 MIDI 채널 | |

음 이름은 큐베이스 표기를 따릅니다 (가운데 도 = C3). 그래서 4현 개방 E는 **E0**, 5현 Low B는 **B-1**로 표시됩니다.

## 알아둘 점

- 단음(모노포닉) 전용입니다. 화음은 검출하지 못합니다.
- 저음일수록 파형 한 주기가 길어서 반응이 늦습니다.

## 성능 (실제 베이스 녹음 기준)

Fraunhofer IDMT의 공개 데이터셋(IDMT-SMT-Bass, CC BY-NC-ND 4.0)으로 평가합니다. 하모닉스 주법은 제외했습니다.

| 항목 | 결과 |
|---|---|
| 단음 약 4,300개, 피킹에 대한 노트 정확도 | 91.8% (핑거 99%, 피크 99%, 비브라토 97%, 벤딩 97%, 뮤트 93%, 슬랩 팝 80%, 슬랩 썸 78%) |
| 노트가 켜지고 150ms 뒤 올바른 음 | 95% |
| 실제 베이스 라인 17곡 (Recall / Precision / F1) | 96% / 89% / 92% |
| 데드 노트가 노트로 찍히는 비율 | 20% |
| 반응 지연 (어택 시작부터 Note On까지, 중간값) | 약 47ms (G2 이상 약 42ms, 저음 E~D# 약 60ms) |

실제 피킹은 손가락이 줄에 닿는 순간부터 줄이 제대로 진동하기까지 시간이 걸립니다. 그래서 위 지연의 상당 부분은 물리적으로 음정이 정해지기 전 구간입니다. GitHub Actions의 `Evaluate on real bass recordings` 워크플로가 코드가 바뀔 때마다 이 수치를 다시 측정합니다.

- 오인페의 버퍼 크기가 작을수록 전체 지연이 줄어듭니다.

## 테스트 도구

`bench` 프로그램은 가상 베이스 라인으로 정확도와 반응 속도를 측정합니다. WAV 파일을 넣으면 검출된 노트 목록을 출력합니다.

```
bench              # 가상 테스트
bench my_bass.wav  # 실제 녹음 분석
```

## 직접 빌드하기

Visual Studio 2022와 CMake가 있으면 됩니다.

```
cmake -B build -A x64
cmake --build build --config Release
```
